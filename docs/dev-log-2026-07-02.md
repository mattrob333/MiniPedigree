## 3. Long-transcript pipeline (commit `8878139`)

Requirement: 30–60+ minute Teams/Google Meet transcripts must never fail on size (this
had caused real failures before).

- `src/lib/transcript.ts` (shared client/server):
  - `normalizeTranscript` — strips WebVTT headers/cues/timestamp ranges, `<v Speaker>`
    tags, Teams "Name 0:03" headers, Zoom "From" lines, bare/inline timestamps; merges
    consecutive same-speaker captions. Real exports shrink 2–4×.
  - `chunkTranscript` — speaker-boundary chunks (60K chars default) only when needed.
  - `mergeParsedDiscoveries` — unions per-chunk results by person/responsibility/task.
- Client normalizes before upload (stays far under Vercel's hard ~4.5 MB body cap);
  local fallback parser gets clean text too.
- Server: **size rejection removed entirely** — normalize → chunk → parallel model calls
  → merge. Uploaded context-document text is bounded in the prompt instead (transcripts
  are never truncated). Express body limit 4 → 20 MB.
- Tests include a synthetic 900-caption meeting (first and last utterances survive).

## 5. Audit ledger v0 + evidence pack (this commit)

- `src/lib/audit.ts` — append-only, hash-chained event log per workspace
  (`workspace_created`, `session_applied`, `org_sync_applied`, `agent_generated` with its
  SOD findings, `context_documents_uploaded`, `company_profile_saved`,
  `export_performed`). Each event's hash covers its content + the previous hash;
  `verifyAuditChain` detects any edit, deletion, or reorder. v0 chain is FNV-1a 64-bit —
  tamper-evident, honestly labeled; production path is a server-side SHA-256 ledger
  behind auth.
- Ledger persists with the workspace (localStorage + Supabase snapshot), survives
  reloads, and travels with workspace hand-offs.
- **Compliance tab** now shows the audit trail (reverse-chron, actor, type, summary) with
  a live `chain intact` / `chain broken at #n` badge.
- `src/lib/evidence.ts` — **Export evidence pack**: one zip with `README.md` (summary +
  chain verification + how to re-verify), `audit-log.json` + `audit-log.csv`,
  `sod-findings.json` (person- and agent-level), `org-snapshot.csv`,
  `company-profile.json` (document texts referenced, not embedded), and
  `manifests/*.json` for every generated agent.
- Tests: chain append/verify/tamper/delete/reorder + evidence-pack content assertions
  (zip opened and inspected in the test).

## Addendum (same day) — org-sync SOD checks + prompt-injection hardening

**SOD on org-sync changesets** (closes the gap where the demo playbook promised it):
- `computeChangeset` now runs the SOD engine on each person's *prospective* duty set
  (current tasks + agents + incoming handoffs) and reports only conflicts the handoff
  would **create** — pre-existing ones stay on the Compliance tab.
- Org Sync review modal: red "SOD conflict" chip + explanation panel on the affected
  person's card, an SOD-conflicts summary tile, and conflicted deltas default to
  **unapproved** (clean ones default on). Approving anyway is logged to the audit
  ledger as an explicit override with rule ids.
- Fixed rule **SOD-04**: "release blocked orders" was on the order-entry side of the
  duty pair; it is a credit-side function (same side as setting limits). Old behavior
  wrongly flagged a credit manager doing her own job and missed the real violation
  (order entry + credit release). Policy text updated to match.
- Deterministic extractor gained `enters/quotes/sets` verbs so real order-desk phrasing
  parses without an API key. Scenario D's transcript is now verified end-to-end via
  Playwright (chip, panel, and unapproved default all confirmed in the built app).

**Prompt-injection hardening** (`server/core/untrusted.ts`):
- Transcripts, user notes, and company profiles (including web-researched content) are
  wrapped in explicit `[BEGIN/END UNTRUSTED ... DATA]` blocks, and every system prompt
  (discovery parse, agent author, company profile) carries a standing rule to treat
  embedded instructions as data and surface the attempt.
- `clampAuthoredSpec` (server-side, deterministic, unit-tested): any model-requested
  `full` MCP scope is downgraded to `draft_only` with an annotated reason — the code
  now keeps the promise the prompt was already making. Client keeps its own downgrade;
  defense in depth.
